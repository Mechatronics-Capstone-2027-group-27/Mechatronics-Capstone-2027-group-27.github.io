    # Work Done
    - JSBSim includes an aircraft creation utility, called Aeromatic++, which generates approximate aircraft model files based on a set of input parameters. It was attempted to use this for the initial glider model using the parameters from the old MATLAB script; however, this resulted in the glider exceeding the speed of light in a fraction of a second.
    - In light of the failure of the Aeromatic++ utility, an existing glider model from JSBSim, the SGS 233, was used as a baseline and modified.
    - Approximate aspect ratios were used from the Stratodynamics HiDRON glider, with a wingspan assumed at 10m, and a vertical stabilizer height of 1m.
    - Glider weight was modeled as 3kg, with equal payload weight, giving 1:1 glider:payload ratio
    - XFOIL script was fixed, runs each combination of alpha and Re separately in order to avoid the crashes which happen when running the scripts as a large series batch using the ASEQ command.

    # Results
    - JSBSim simulation is stable and gives physically reasonable results
    - Flight behavior is very different at 10km altitude compared to 40km altitude, high altitude gives strong oscillations at the beginning of the flight
    - Location of center of gravity has strong impact on flight dynamics and glider performance

Given the new approach of using JSBSim as a flight dynamics model instead of rewriting a custom dynamics model, the estimate dimensions and layout of the model must be rewritten into the format used by JSBSim for accurate simulations. JSBSim uses XML file input with specific formatting to store aircraft properties. Aerodynamic data must still be generated by XFOIL and imported into the JSBSim XML file.
